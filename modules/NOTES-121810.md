# CVE-2026-121810 — HTTP/3 (QUIC) ストリーム生成中の drain による親接続 UAF

- モジュール: `modules/121810.py`（自己完結）
- 対象: nginx 1.31.8（`build/inst-vuln/sbin/nginx`）と nginx 1.31.9（`build/inst-fixed-v3/sbin/nginx`、`--with-http_v3_module` 付き新規ビルド）
- 作業ディレクトリ: `poc-run-C`（QUIC/UDP 18446、TCP/TLS 18447 のみ使用）
- 結果: 1.31.8 = CRASH（signal 11） / 1.31.9 = TRIGGERED（クラッシュせず）

---

## 1. 脆弱性の仕組み

`ngx_quic_create_stream()`（1.31.8）は、新しいストリームを rbtree へ挿入する前に
`ngx_get_connection()` を呼ぶ。空き接続が尽きると `ngx_get_connection()` が
`ngx_drain_connections()` を実行し、reusable キューから接続を閉じる。

```
static ngx_quic_stream_t *
ngx_quic_create_stream(ngx_connection_t *c, uint64_t id)      /* 1.31.8 */
{
    ...
    reusable = c->reusable;
    ngx_reusable_connection(c, 0);

    sc = ngx_get_connection(c->fd, log);      /* ← ここで drain が走る */
    ...
    ngx_rbtree_insert(&qc->streams.tree, &qs->node);   /* ← 挿入は後 */
    return qs;
}
```

1.31.9 の修正（`v1.31.8` と `v1.31.9` の diff）:

```
+    ngx_rbtree_insert(&qc->streams.tree, &qs->node);
+
     reusable = c->reusable;
     ngx_reusable_connection(c, 0);
 
     sc = ngx_get_connection(c->fd, log);
     if (sc == NULL) {
         ngx_destroy_pool(pool);
+        ngx_rbtree_delete(&qc->streams.tree, &qs->node);
     ...
-    ngx_rbtree_insert(&qc->streams.tree, &qs->node);
```

### 発生手順（本 PoC が再現するもの）

1. 親 QUIC 接続をアイドル（reusable キュー）にしておく。
2. ストリーム `0x0` を `STOP_SENDING` で生成する。nginx は `RESET_STREAM` を返し、
   クライアントが ACK すると `send_state = RESET_RECVD`、`recv_state = RECV` になる。
   このストリームは「ヘッダ待ちのアイドルストリーム」として reusable キューに残る。
3. worker_connections を 16 に絞り、TCP/TLS 18447 へのダミー接続（ClientHello の
   1 バイト目 `0x16` だけ送ってハンドシェイクを止める）で空きスロットを 1 個にする。
4. 同一 UDP データグラムに次を載せる：
   - `STREAM id:0x0 len:0 fin:1`（ストリーム 0x0 の FIN）
   - `STREAM id:0x4 len:18 fin:1`（完全な HTTP/3 リクエスト。`proxy_pass` 対象）
5. nginx は 0x0 の FIN を処理して read イベントを post するが、まだ実行しない。
   続いて 0x4 のフレームを処理し「ストリーム 0x4 が無い」ので
   `ngx_quic_create_stream(親, 0x4)` を呼ぶ。
6. `ngx_get_connection()` → drain → reusable キューの `*12`（=stream 0x0）を close。
   0x0 は send=RESET_RECVD / recv=DATA_RECVD なので `ngx_quic_close_stream()` が
   最後まで進み、`ngx_quic_can_shutdown()` が「他に非キャンセル可能ストリーム無し」
   と判定する（生成中の 0x4 はまだ rbtree に無い）。→ 親 `*1` が reusable へ誤って復帰
   （ログ: `*1 quic stream id:0x0 close` の直後の `*1 reusable connection: 1`）。
7. ストリーム 0x4 のリクエストが `proxy_pass` に進み、upstream 接続取得の
   `ngx_get_connection()` が再び drain を実行 → reusable キューの先頭に残っていた
   親 `*1` が選ばれ close される。進行中のリクエスト（`*13`）が
   `ngx_http_free_request()` で解放され、`ngx_event_connect_peer()` に戻った後で
   解放済みメモリを参照する use-after-free になる。

1.31.9 では手順 5 の `ngx_get_connection()` 時点で 0x4 が既に rbtree にあるため
`ngx_quic_can_shutdown()` が `DECLINED` を返し、親は reusable へ戻らない。
そのため手順 7 の drain でも親は選ばれず、クラッシュしない。

## 3. モジュール

`modules/121810.py` の公開 API:

```python
run(binary: str, workdir: str, host: str = "127.0.0.1") -> dict
# -> {"cve": "CVE-2026-121810", "configured": bool, "trigger": bool,
#     "effect": "UAF"|"CRASH"|"TRIGGERED"|"ERROR"|"SKIP", "detail": str}
```

- 自分で `nginx.conf` と自己署名証明書を `workdir` 配下に生成（証明書・鍵は `chmod 644`）
- `worker_processes 1; worker_connections 16;`
- 起動は `binary -p <workdir>/ -c <workdir>/nginx.conf`、停止は pid ファイル +
  `/proc` 走査（`pkill` 不使用）。停止は SIGQUIT → 必要なら SIGTERM/SIGKILL。
- 接続スロット調整のため最大 4 回まで HOLD 数（8, 9, 7, ...）を変えて再試行。
  drain が走ったのに落ちない場合は修正版と判断（2 回確認）。

生成される `nginx.conf`（実行時の原文）:

```nginx
worker_processes 1;
daemon on;
pid /app/data/sessions/conv-43/poc-run-C/nginx.pid;
error_log /app/data/sessions/conv-43/poc-run-C/logs/error.log debug;
events { worker_connections 16; }
http {
    access_log off;
    client_body_temp_path /app/data/sessions/conv-43/poc-run-C/tmp;
    ssl_certificate /app/data/sessions/conv-43/poc-run-C/certs/cert.pem;
    ssl_certificate_key /app/data/sessions/conv-43/poc-run-C/certs/key.pem;
    server {
        listen 127.0.0.1:18447 ssl;
        listen 127.0.0.1:18446 quic reuseport;
        http3 on;
        location / {
            proxy_pass http://127.0.0.1:18447;
        }
    }
}
```

クライアント側（aioquic）の要点:

- 静的テーブルのみの QPACK で `:method GET / :scheme https / :path / / :authority localhost`
  を組み立て、`HEADERS` フレームを生の `send_stream_data()` で送る（H3Connection は使わない）。
- `0x0` は `send_stream_data(0, b"", end_stream=False)` でローカル生成してから
  `stop_stream(0, 0)`。`RESET_STREAM` の ACK を待つため 0.5 秒待機。
- 最後に `send_stream_data(0, b"", end_stream=True)` → `send_stream_data(4, HEADERS, end_stream=True)`
  の順で呼び、1 回の `transmit()` で同一データグラムに載せる（aioquic は
  `_streams_queue` の FIFO 順で STREAM フレームを書き出す）。

## 6. 注意点

- 使用ポートは QUIC/UDP 18446 と TCP/TLS 18447 のみ。18447 は
  (a) 接続スロットを埋めるダミー接続（ClientHello 1 バイトで停止）と
  (b) `proxy_pass` の upstream 先（plain HTTP を投げるので 400 が返るが、
      UAF は upstream 接続取得時点で起きるため応答は不要）に共用。
- `worker_connections 16` が本再現の要。大きすぎると drain が発動せず、
  小さすぎるとストリームが生成できない。モジュールは HOLD 接続数で微調整する。
- 停止は pid ファイル + `/proc` 走査（`pkill` 不使用）。証明書・鍵は `chmod 644`。
- `full-poc.py` は編集していない。
